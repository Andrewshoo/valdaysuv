# Админка и передача наполнения

## Что подготовлено

Адрес после публикации: https://valdaysuv.ru/admin/

В Decap CMS настроены товары, галерея, категории, контакты и тексты мастерской.
Данные хранятся на GitHub в JSON. Опубликованное содержимое доступно посетителям
как готовый HTML; браузеру и поисковому роботу не нужен запрос к базе данных.
Заказы и персональные данные покупателей не записываются в этот репозиторий.

Авторизация: GitHub через OAuth-сервис Netlify. Пароли и client secret в код
не добавляются. Git Gateway и Netlify Identity не используются.

## Однократная настройка владельцем

1. Войти в Netlify и создать проект для OAuth. Можно импортировать этот репозиторий:
   build command `python scripts/build.py`, publish directory `dist`.
   Файл netlify.toml задаёт эти значения. Домен valdaysuv.ru НЕ переносить,
   DNS не менять: основной сайт продолжает работать на GitHub Pages.
2. Записать выданный Netlify адрес проекта вида `имя-проекта.netlify.app`.
   В `admin/config.yml` заменить `backend.site_domain` на это имя хоста,
   БЕЗ `https://` и `/`. Текущее значение valdaysuv.ru применимо только если
   этот домен зарегистрирован для OAuth-проекта в Netlify; до настройки вход
   не считается рабочим. `site_url` и `display_url` оставить valdaysuv.ru.
3. Создать GitHub OAuth App: https://github.com/settings/developers → OAuth Apps.
   Homepage URL: https://valdaysuv.ru/
   Authorization callback URL: https://api.netlify.com/auth/done
4. В Netlify Project configuration → Security → OAuth → Authentication Providers
   установить GitHub и ввести Client ID и Client Secret приложения.
   Secret вводится только в интерфейсе Netlify, не в репозитории и не в чате.
5. Проверить, что GitHub Pages использует GitHub Actions, а последний запуск
   Build and deploy website завершился успешно.
6. Открыть https://valdaysuv.ru/admin/ и войти через GitHub. При работе локально
   нужно открывать страницу через HTTP-сервер, не через file://.
7. Выполнить пробное изменение: сохранить черновик, проверить pull request и
   успешную сборку, затем опубликовать и проверить сайт. Только после этого
   передавать наполнение сотруднику.

Netlify-проект может быть техническим зеркалом для OAuth. Для него настроен
заголовок X-Robots-Tag: noindex; канонический адрес страниц — valdaysuv.ru.
Не отключайте OAuth-проект после настройки: он нужен для входа в CMS.

## Доступ сотруднику

Для backend github сотруднику нужен GitHub-аккаунт и доступ Write к репозиторию.
Это даёт права записи в репозиторий, а не только доступ к экрану CMS.
Не передавайте свой аккаунт, пароль или OAuth Secret.
Если позже понадобятся строго ограниченные роли редактора без доступа к коду,
нужно выбрать другую архитектуру авторизации/CMS.

Включён editorial_workflow: черновик сохраняется в отдельной ветке и pull request;
публикация объединяет его с main. Сам workflow не запрещает сотруднику с правами
Write публиковать. Для обязательного одобрения владельцем настройте защиту main
с требованием pull request и review, проверив возможности тарифа GitHub.

## Наполнение

1. Открыть раздел «Товары» → добавить товар.
2. Заполнить название, категорию, номер модели (0, если номера нет), описание,
   размеры, фото, цену и наличие. Пустая цена означает «Цена по запросу».
3. Сохранить черновик, проверить, затем опубликовать. Дождаться зелёной сборки.
4. Для галереи использовать «Галерея работ»: название, фото, подпись, тема.
5. В «Настройках сайта» редактируются категории, контакты и основные тексты.

Фото загружать в img/uploads; не загружать пароли, документы клиентов и другие
персональные данные. Описание — обычный текст, HTML и Markdown не исполняются.
При смене названия товара не переименовывайте его JSON-файл: имя файла определяет
стабильный ID новых товаров. Существующие служебные ID скрыты в админке.
Не удаляйте категорию, пока к ней привязаны товары: сборка остановится с ошибкой.
Порядок моделей внутри категории — по номеру, затем по полю порядка.
В галерее поле порядка определяет расположение фотографий.

Часы работы сейчас задаются на каждый день одинаково. Telegram и Макс остаются
в коде src/script.js; их смена требует разработчика. Телефон, email и адрес
самовывоза в тексте заказа берутся из настроек сайта.

## Проверка и откат

Если сборка красная, предыдущая опубликованная версия остаётся на сайте.
Посмотрите ошибку в Actions: частые причины — отсутствующее фото, повторяющийся
ID, неверный номер модели, цена или удалённая категория.
Для отката владелец отменяет ошибочный коммит через revert и ждёт новой сборки.

Содержимое открытого репозитория публично, включая файлы черновиков в ветках.
В них не должно быть конфиденциальной информации.
